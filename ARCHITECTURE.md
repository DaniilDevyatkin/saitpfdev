# Архитектура платформы «Шесть»

Документ объясняет, почему платформа устроена именно так. Каждое решение
записано вместе с альтернативой, которую пришлось отклонить, — чтобы через
месяц не восстанавливать ход мысли по коду.

## 1. Задача

Шесть репозиториев, четыре разных технологии (FastAPI, React + Vite,
Next.js + Fastify, статический HTML/CSS/JS). Нужна одна точка входа, которая
не переписывает проекты, а показывает их вживую и связывает общим сценарием.

## 2. Решение: один процесс-агрегатор + отдельные стенды

Платформа (`studio/`) — FastAPI-приложение, которое:

1. отдаёт портал с реестром и страницами проектов;
2. монтирует три статических лендинга как настоящие пути `/p/<slug>/`;
3. монтирует сервис согласования из `TestovoeDevyatkin` подпрефиксом
   `/svc/approval` в тот же процесс;
4. проверяет здоровье всех компонентов и отдаёт сводку в `/api/health`.

Приложения, которым нужен собственный сервер, работают отдельными юнитами:

- `kartochki-stand` — `uvicorn main:app` на `:8200`, отдаёт собранный React и API;
- `igrushki-api` — Fastify на `:3301` (REST + WebSocket + SQLite);
- `igrushki-web` — Next.js standalone на `:3100`.

### Почему не «всё под одним префиксом»

Next.js и Vite-сборки ссылаются на ассеты абсолютными путями (`/_next/...`,
`/assets/...`) и обращаются к API по абсолютному адресу. Подключение под
`/p/igrushki/` требует либо `basePath` в их конфигурации, либо переписывания
HTML/CSS на лету в прокси. Первое — правка чужих репозиториев, второе — хрупкий
слой, который ломается на каждом ассете. Поэтому стенды живут на своих портах,
а портал встраивает их через `iframe` и даёт прямую ссылку. Статические лендинги,
у которых все пути относительные, смонтированы по-настоящему — без прокси и
без iframe.

### Почему сервис согласования вмонтирован, а не запущен рядом

У него нет состояния вне SQLite и нет фоновых задач: это чистый HTTP-сервис.
Вмонтировать его в процесс платформы дешевле (один юнит вместо двух) и полезнее
для демонстрации: витрина и сервис живут в одном процессе, без CORS и лишних
сетевых хопов. Единственная тонкость — вложенные приложения Starlette
не запускают собственный `lifespan`, поэтому схема создаётся явно в
`studio/approval.py` вызовом `Base.metadata.create_all`.

База переезжает переменной `DATABASE_URL` в `data/approval.db`. Код донора не
менялся ни на строку.

## 3. Данные вместо разметки

Реестр не хранится в шаблоне. `scripts/inventory.py` обходит репозитории,
считает файлы, строки по языкам и объём, читает последний коммит и пишет
`docs/inventory.json`. Портал превращает этот JSON в объекты `Project` и
рендерит их. Следствия:

- цифры на витрине невозможно «забыть обновить»;
- добавить седьмой проект — это запись в `META` и повторный запуск скрипта;
- любой спор о метрике решается запуском скрипта, а не доверием к тексту.

## 4. Проверка живости

`/api/health` опрашивает компоненты параллельно (`asyncio.gather`, таймаут 2 с,
кэш 5 с) и возвращает по каждому: имя, путь, роль, отклик в миллисекундах и
состояние. На витрине эта таблица не показывается — она снята как лишний шум;
эндпоинт остаётся машинной проверкой и источником правды о том, что живо.
Статические лендинги проверяются наличием `index.html`, стенды — HTTP-запросом
к их health-пути.

## 5. Безопасность

- Никаких секретов в репозитории: `JWT_SECRET` для «Игрушечек» лежит в
  `.env.stands` (права 600, исключён из git).
- Заголовки `X-Content-Type-Options: nosniff`, `Referrer-Policy`,
  `X-Frame-Options: SAMEORIGIN` ставятся middleware для всех ответов платформы.
- Статика отдаётся `StaticFiles`, который нормализует путь: обход каталогов
  через `../` возвращает 404 (проверяется тестом).
- Сервис согласования продолжает требовать `X-Workspace-ID`, `X-User-ID` и
  `X-Actions`; наружу торчит только документация `/svc/approval/docs`.
- Наружу ничего не публикуется: платформа слушает локальную сеть.

## 6. Оформление

Дизайн-система вынесена в `DESIGN.md` до вёрстки: палитра, три гарнитуры,
запреты, сигнатурный элемент («реестр» — полноширинные строки-записи с живым
превью). Шрифты лежат локально (`studio/static/fonts`, 15 файлов woff2),
поэтому портал рисуется без доступа в интернет, а внешние CDN не влияют на
скорость и приватность.

## 7. Что осталось за рамками

- Сквозная авторизация между порталом и стендами: сейчас у каждого стенда своя
  сессия. Для демонстрации это не нужно, для продукта — обязательный шаг.
- Сборка «Игрушечек» требует Node 22 (в системе стоит 26, под которым
  `better-sqlite3` не собирается). Node 22 распакован в `/home/fun/local/node22`
  и прописан в юнитах явно.
- Публикация на домен, TLS и внешний прокси не настраивались: по договорённости
  сначала объясняем и спрашиваем.
