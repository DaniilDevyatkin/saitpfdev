# Отчёт: сборка платформы «Шесть»

Дата: 19 ноября 2026. Автор работы: Hermes (агент), заказчик: Даниил Девяткин.

## Что было на входе

Шесть репозиториев GitHub, четыре разных технологических стека:

- `TestovoeDevyatkin` — FastAPI, сервис согласования, SQLite + Alembic;
- `TestovoeBug` — статический каталог на HTML/CSS/JS;
- `BelberryTestovoe` — статический промо-лендинг, 11 CSS-файлов, ванильный JS;
- `Igrushki` — Next.js 16 + React 19 + Fastify + WebSocket + SQLite, 26 тысяч строк;
- `TestovoeKartochki` — FastAPI + Pillow на сервере, React + Vite на клиенте;
- `TestovoeUsmanova` — реплика лендинга на Bootstrap + jQuery (GetCourse).

Суммарно: **34 153 строки кода**, **303 файла**, **483 МБ** с картинками и медиа.

## Что сделано

1. **Клонирование.** Все шесть репозиториев склонированы в `repos/` по SSH
   (два из них приватные — публичный HTTPS их не отдаёт).
2. **Инвентаризация.** `scripts/inventory.py` обходит репозитории и собирает
   `docs/inventory.json`; `scripts/render_inventory.py` печатает
   `docs/INVENTORY.md`. Цифры на витрине берутся только отсюда.
3. **Платформа.** Приложение `studio/` на FastAPI:
   - портал с реестром и страницами проектов;
   - три лендинга, смонтированные реальными путями `/p/<slug>/`;
   - сервис согласования из проекта №1, вмонтированный под `/svc/approval`
     без единой правки его кода;
   - сводный health-check `/api/health` и машинный каталог `/api/catalog`;
   - HTTP-API согласования и машиночитаемый health-check (`/api/health`,
     `/api/catalog`); интерфейсных консолей на витрине нет — сняты по просьбе
     владельца как лишние.
4. **Стенды приложений.**
   - «Карточки»: React собран Vite, FastAPI отдаёт API и статику на `:8200`;
   - «Игрушечки»: Next.js standalone на `:3100`, Fastify + WebSocket на `:3301`,
     SQLite, миграции применяются при старте.
5. **Дизайн.** `DESIGN.md` до вёрстки: палитра, три гарнитуры (Unbounded,
   Golos Text, JetBrains Mono), сигнатурный элемент «реестр», запреты.
   Шрифты скачаны локально (15 файлов woff2, 420 КБ) — портал рисуется без
   интернета.
6. **Эксплуатация.** Четыре systemd-юнита пользователя с автозапуском:
   `portfolio-platform`, `kartochki-stand`, `igrushki-api`, `igrushki-web`.
   Плюс `run.sh` для запуска без systemd и `.env.stands` с секретом стенда.
7. **Документация.** `README.md`, `ARCHITECTURE.md`, `DESIGN.md`, этот отчёт,
   `docs/INVENTORY.md`.

## Что сломалось по дороге и как починено

1. **Два репозитория не клонировались по HTTPS** — приватные. Перешёл на SSH-ключ
   `~/.ssh/id_ed25519_github`, который уже был настроен в системе.
2. **`TestovoeKartochki` (349 МБ) не успел склонироваться** за отведённые
   300 секунд — клонирование ушло в фон и завершилось.
3. **`better-sqlite3` не собирался.** Сначала npm заблокировал install-скрипты,
   потом выяснилось, что в системе нет `make`/`g++`, а под Node 26 у модуля нет
   готового бинарника. Решение: распаковал Node 22 LTS в `/home/fun/local/node22`
   без root и пересобрал зависимости под него — прекомпилированный бинарник
   встал сразу.
4. **Стенд «Игрушечек» падал при старте** на поиске миграций: код ищет
   `src/db/migrations` относительно `process.cwd()`. Запуск перенесён в каталог
   `server/`, где миграции и лежат.
5. **`.env` с `JWT_SECRET` ломал сервис согласования** — его pydantic-настройки
   читают `.env` из рабочего каталога и падают на лишнем поле. Файл переименован
   в `.env.stands`, юнит указывает на него явно.
6. **Мобильная вёрстка давала горизонтальный скролл 68 px** — виновата таблица
   статуса. На узких экранах скрыты служебные колонки, скролл стал нулевым
   (проверено в браузере: `scrollWidth - clientWidth === 0`).
7. **Параллельно стартовавшие kanban-воркеры** успели создать вторую реализацию
   платформы в том же каталоге. Дубли удалены, оставлена одна рабочая ветка
   (`studio/`), из чужого черновика ничего не тащил — своя реализация уже была
   проверена вживую.

## Что сознательно не сделано

- **Публикация в интернет.** По договорённости с владельцем сначала объясняю и
  спрашиваю. Сейчас платформа слушает локальную сеть: `http://192.168.51.81:8110`.
- **Единая авторизация между порталом и стендами.** У каждого стенда своя сессия;
  для витрины это не нужно, для продукта — следующий шаг.
- **Проксирование стендов под общий префикс.** Потребовало бы `basePath` в
  Next.js и правок в сборке Vite; вместо этого iframe + прямая ссылка.
- **Скриншоты мобильных версий проектов.** Сняты десктопные кадры для реестра.

## Исправление: стенд «Игрушечек» падал по сетевому адресу (19.11.2026, 08:05)

Симптом: страница работы открывалась, а внутри рамки вместо игры — «Экран не
загрузился. Мы уже записали техническую информацию».

Диагностика: по `127.0.0.1:3100` приложение работало, по `192.168.51.81:3100` —
падало. Перехват `console.error` до загрузки дал точную ошибку:
`TypeError: Cannot read properties of undefined (reading 'addEventListener')`
в `ServiceWorkerRegistrar`.

Причина: в компоненте два `useEffect`. Первый проверяет
`"serviceWorker" in navigator`, второй — нет. Service Worker доступен только
в защищённом контексте (HTTPS или localhost), поэтому по обычному `http://`
на сетевом адресе `navigator.serviceWorker` равен `undefined`, и второй эффект
ронял рендер — срабатывал error boundary.

Исправление — одна строка-гард во втором `useEffect` (правка в самом репозитории
`Igrushki`, не в платформе): `if (!("serviceWorker" in navigator)) return;`.
Приложение пересобрано, стенд перезапущен, по LAN-адресу открывается форма входа.
